🧠 Why This Is Happening (Common Causes in Custom Editor Engines)
When a scene renders behind the GUI instead of inside a designated viewport panel, it usually comes down to one or more of these core issues:

🟦 1. Render Target / Swapchain Isn’t Bound Correctly
DirectX (or any low-level renderer) draws to whatever render target is currently bound. If the main swapchain is bound instead of the viewport’s render target, your game world will just draw to the full screen behind the GUI.

What to check:

Confirm that your viewport panel has its own ID3D11RenderTargetView / ID3D12RenderTargetView.

Ensure you call OMSetRenderTargets(...) with that viewport’s RT before drawing the scene.

After scene rendering, you draw GUI on top or composite to the final back buffer.

🏞 2. Camera or Viewport Rect isn’t Applied
Even if you’ve got the right render target, the projection or scissor/viewports might be off. If the world’s camera is still using full-screen coordinates rather than the editor panel’s rectangle, it will draw “full screen”.

What to check:

Before rendering the scene, call something like:

D3D11_VIEWPORT viewport = {};
viewport.TopLeftX = panelX;
viewport.TopLeftY = panelY;
viewport.Width    = panelWidth;
viewport.Height   = panelHeight;
devcon->RSSetViewports(1, &viewport);
Make sure you reset it when drawing UI.

If the engine doesn’t update the rendering viewport properly, the “world camera” will happily render behind everything.

🪟 3. GUI Drawing Happens After Scene but Covers It Improperly
If your GUI uses native Win32 controls or a layer that doesn’t use depth testing, it might always draw on top — but if the world is being drawn to the same render target without depth/stencil setup, the GUI could appear to clip through or hide the world arbitrarily.

What to check:

Is your depth/stencil buffer bound during scene rendering?

Is your GUI rendering layer using its own overlay with proper layering or Z-as-always-on-top?
